# Independent check of the endpoint evaluator

Proposition 10.1 follows from the evaluator constructed in Appendix B.4, Theorem B.7, equation (33). I read the definitions of the numerical category, the tuple diagram, the component functors and the partial evaluator before comparing the argument with the Lean sources.

**The partial function in (33).** At either endpoint the parameter and input have type $\mathbb N^2$. If they are $(k,p)$ and $(l,x)$, respectively, the value is the pair decoded from the output of program $p$ on the code of $(l,x)$. Its domain consists exactly of inputs on which that computation halts. The first parameter coordinate $k$ plays no role. The acceptable numbering, the tuple bijection and its inverse are the ones fixed in Appendix B. A section of a computably enumerable domain can be computably enumerable without being decidable; the construction only needs to enumerate it.

**The parameter in Proposition 10.1.** Let $Z$ be any c.e. numerical carrier and $F:Z\times\mathbb N^2\rightharpoonup\mathbb N^2$ any partial morphism with domain $D$. On ambient input $(z,x)$, wait for $(z,x)$ to appear in an enumeration of $D$, then compute the coded value of $F$. Specialization supplies a computable $s$ on the ambient parameter tuples. Its restriction gives the total morphism $z\mapsto(0,s(z))$ on $Z$. Equation (33) with that parameter has the same domain and values as $F$, including when $D$ or $Z$ is empty. For arity zero, specialization produces a constant program index. Evaluation of spans preserves the listed operations because pullbacks, images, products, coproducts and unions of domain subfunctors are computed vertexwise. **Compatibility at the central vertex.** All three programs must halt there. The two output pairs must be the projections of the central output four-tuple, as in (34). These finite tests define a c.e. domain, and the projection equations make the partial values into a natural transformation on it. For a given partial natural morphism $F:Y\times V\rightharpoonup V$, specialize each restricted component program. At the centre, collect the index for that fibre and the two endpoint indices at the images of the parameter. If the central fibre of $F$ is defined, its image in each endpoint is defined and agrees by naturality, so both tests succeed. Conversely the central evaluator can return a tuple only if the program for that central fibre halts. This gives equality of domains and values at all three vertices and a total natural parameter for arbitrary $Y$. **Failure of universality after central evaluation.** Fix a purported central parameter, and compare the two inputs $(0,0,0,0)$ and $(0,1,0,0)$. They have the same first-endpoint projection. The total recursive map that places their second coordinate in the third output coordinate yields different first-endpoint projections. A parameter for this map would force one endpoint computation to return two distinct values. This rules out central universality even for the singleton parameter object.
